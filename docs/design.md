## 1. Aesthetic Direction

### 1.1 Design Philosophy

PsychEngine is a premium personal learning system. The user spends 40-60 minutes daily reading, practicing, and studying. Every pixel must earn its place.

**Aesthetic**: Refined dark, knowledge-forward. The feeling of a well-designed reading app crossed with a high-end productivity tool. Think Linear's precision, Superhuman's speed, and a great reading app's comfort.

**NOT**: a generic dashboard, a Bootstrap template, a Material Design clone, a purple-gradient AI app, or anything that looks like it was generated by an LLM without direction.

**Core feelings the UI must evoke:**
- Calm focus (not overstimulating)
- Intellectual sophistication (not corporate sterility)
- Quiet confidence (not flashy or desperate for attention)
- Depth and richness (not flat or lifeless)

### 1.2 Design Principles for Every Decision

1. **Hierarchy is everything**: the most important element on any screen should be immediately obvious. Use size, weight, contrast, and spacing to create a clear visual path.
2. **Restraint over excess**: one accent color used well beats five scattered everywhere. One animation at the right moment beats twelve competing for attention.
3. **Consistency is non-negotiable**: if a card looks one way on the dashboard, it looks exactly the same way on the topic page. No one-off styling.
4. **Space is a feature**: generous whitespace makes content feel premium. Cramped layouts feel cheap.
5. **Content is king**: the UI serves the reading experience. Never let decoration compete with content.

**Font Loading**: load Clash Display (display), Satoshi (body), Source Serif 4 (reading), and JetBrains Mono (code) from Google Fonts or Fontsource. Use `font-display: swap`.

**Usage Rules**:
- `--font-display`: page titles, dashboard hero numbers, section headings
- `--font-body`: all UI text, navigation, buttons, labels, descriptions
- `--font-reading`: book reader content, topic page content, long-form text
- `--font-mono`: code snippets, data values, quiz timers, stats

**NEVER USE**: Inter, Roboto, Arial, Open Sans, Lato, system-ui as a visible font. These are fallbacks only.

**Rules**:
- Padding inside cards: `--space-5` (20px) minimum, `--space-6` (24px) preferred
- Gap between cards in a grid: `--space-4` (16px) minimum, `--space-5` (20px) preferred
- Section spacing (between major sections on a page): `--space-12` (48px) minimum
- Page padding (left/right margin of main content): `--space-8` (32px) on desktop, `--space-4` (16px) on mobile
- Never use arbitrary pixel values. Every spacing value must come from this scale.

## 3. Component Specifications

.card-grid > *:nth-child(6) { animation-delay: 300ms; }

## 6. Skeleton Loading States

Never use spinners. Use skeleton screens that match the layout of the content being loaded.

```css
.skeleton {
  background: linear-gradient(
    90deg,
    var(--surface-hover) 25%,
    var(--surface-active) 50%,
    var(--surface-hover) 75%
  );
  background-size: 200% 100%;
  animation: skeleton-shimmer 1.5s ease-in-out infinite;
  border-radius: var(--radius-md);
}

@keyframes skeleton-shimmer {
  0% { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
```

Skeleton shapes must match the content they replace:
- Text line: 60-80% width, 16px height, 8px margin bottom
- Card: exact card dimensions with internal skeleton lines
- Avatar: circle, exact size
- Image: exact aspect ratio rectangle
- Chart: approximate chart shape

## 7. Empty States

Every page and section must have a designed empty state. Never show a blank area.

```
Structure:
  - Centered in the available space
  - Icon or illustration (subtle, monochrome, 48-64px)
  - Title: --text-lg, --weight-semibold, --text-primary
  - Description: --text-sm, --text-secondary, max-width 320px
  - CTA button (if applicable)

Examples:
  - No field reports: "Your journal is empty. After your next conversation, come back and log what happened."
  - No flashcards: "Flashcards appear as you study topics. Start your first session to generate them."
  - No quiz results: "Complete a quiz to see your results here."
  - Search no results: "No matches for '[query]'. Try different keywords."
```

## 9. Anti-Patterns (What NOT To Do)

This section is critical. Claude Code must avoid these patterns.

### 9.1 Visual Anti-Patterns

- **NO** purple gradients on dark backgrounds (the #1 AI-slop indicator)
- **NO** Inter, Roboto, Arial, Open Sans, or Lato as the primary visible font
- **NO** pure black (#000000) backgrounds. Use rich dark tones.
- **NO** pure white (#ffffff) text on dark mode. Use slightly warm off-whites.
- **NO** neon colors. All accents are vivid but not glowing unless intentionally used for glow effects.
- **NO** generic card layouts with no visual hierarchy (where every card looks the same and nothing stands out)
- **NO** centered-everything layouts. Use left-aligned content with intentional spatial hierarchy.
- **NO** border-radius: 20px+ on everything. Keep it subtle and consistent.
- **NO** browser-default form styling. Every input, select, textarea must be custom styled.
- **NO** generic Material Design or Bootstrap-style components.

### 9.2 Structural Anti-Patterns

- **NO** pages with only content and no visual anchors (icons, color coding, progress indicators)
- **NO** walls of text without visual breaks (use spacing, cards, dividers, subtle backgrounds)
- **NO** inconsistent spacing (if cards have 20px padding on one page, they have 20px on every page)
- **NO** deep nesting of navigation (max 2 levels: section > item)
- **NO** infinite scroll without visual progress indicators
- **NO** loading spinners. Use skeleton screens.
- **NO** empty areas without designed empty states.

### 9.3 Interaction Anti-Patterns

- **NO** instant page transitions (no animation = jarring)
- **NO** hover states that only change cursor. Add background or color shift.
- **NO** buttons without visible hover/active/focus states
- **NO** focus indicators that use only outline: auto. Custom focus rings using box-shadow.
- **NO** animations longer than 600ms for UI elements (feels sluggish)
- **NO** animations on every element (select high-impact moments)

## 10. Iconography

Use Lucide Icons (lucide.dev) as the icon set. They are clean, consistent, 24x24 default, and open source.

```
Usage:
  - Navigation icons: 20px, --text-secondary color
  - Card icons: 16px, --text-tertiary color
  - Action buttons: 18px, inherits button text color
  - Empty state icons: 48px, --text-tertiary color
  - Always use stroke-width 1.75 (slightly thinner than default 2 for elegance)
```

Do NOT use Font Awesome, Material Icons, or emoji as icons.

## 11. Data Visualization Style

All charts and graphs follow the app's color system.

```
Chart backgrounds: transparent (sits on card background)
Grid lines: var(--chart-grid), 1px, dashed or dotted
Axis labels: var(--font-mono), var(--text-xs), var(--chart-axis)
Data colors: use --chart-1 through --chart-6 in order
Tooltip: same as component tooltip specification (section 3.7)
Line charts: 2px stroke width, rounded line-cap
Bar charts: border-radius 4px on top corners
Sparklines: 1.5px stroke, no axis, no grid, just the line + optional fill with 0.1 alpha
```

Use Chart.js with minimal configuration, or D3.js for the dependency graph. Strip all default chrome (no default titles, no default legends unless needed, no default grid lines).

Add this block to your project's CLAUDE.md:

## Design System

All frontend code must follow the design system defined in DESIGN.md at the project root.

- [ ] Has focus state (keyboard accessible)
- [ ] Has active/pressed state
- [ ] Has disabled state (if applicable)

- [ ] Has empty state (if applicable)
- [ ] Has error state (if applicable)

- [ ] Border radius follows the scale
- [ ] Transitions use defined durations and easing curves
- [ ] Works at all three breakpoints (desktop, tablet, mobile)
